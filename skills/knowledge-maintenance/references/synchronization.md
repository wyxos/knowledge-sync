# Bootstrap synchronization

After a root bootstrap change, follow the service's current client synchronization policy and installation record. Run the maintained knowledge-sync command for each required machine/harness, preserve personal text outside its managed block and verify the managed content matches the new bootstrap.

The same command installs/updates this bundled skill for detected supported local harnesses. Read the installer documentation and actual options before repair; preserve unrelated skills, registrations and settings. A skill installation is independent of MCP authorization.

A remote shell may lack access to an OS credential store even when the desktop is signed in. Use a supported authenticated local context, or fetch a freshly verified bootstrap through the authorized connected service and pass it using the installer's bootstrap-file option. Keep that temporary file in protected task storage and do not copy OAuth sessions between machines.

Verify per-machine bootstrap files and any account-synced rule separately. Refresh/restart only the clients the current policy requires and respect active work; report a pending client refresh if it cannot be completed without interrupting another task. Do not certify an old local copy or an inaccessible client's state as current.
